# 0.13.11

- **pi runs one copy of the plugin per session.** pi loads a project and a
  global install side by side, and both ran: the standing context loaded
  twice, and each copy rewrote the single `ach-memory` entry in the user-wide
  `~/.pi/agent/mcp.json`, so a session used whichever copy wrote last, often
  an older one. The first copy loaded (the project's) now owns the session and
  registers the server for it with `pi.registerMcpServer`; nothing is written
  to `mcp.json`, and the entry older releases wrote there is removed, since it
  would win over the registration. An entry of another shape is left alone. A
  pi without `registerMcpServer` still gets the entry written.

An older copy still installed elsewhere writes its entry back when it loads:
update every pi install of the plugin (`ach-cli environment hydrate <env> -g
--target pi` for a global one).

Deploy: the plugin. The server is unchanged apart from its version.
