# 0.5.0

Each host installs with its own native plugin command, and nothing of ours runs
first:

```bash
claude   plugin marketplace add ackstorm/ach-memory && claude plugin install ach-memory@ach-memory
codex    plugin marketplace add ackstorm/ach-memory && codex  plugin add     ach-memory@ach-memory
opencode plugin ach-memory@git+https://github.com/ackstorm/ach-memory.git --global
pi       install git:github.com/ackstorm/ach-memory
```

- **The plugin is the repository root.** `plugins/{claude-code,codex,opencode,pi,shared}/`
  is gone, and with it `make plugins`, `make plugins-check` and five copies of
  `SKILL.md` kept byte-identical by a Makefile. The marketplace entry is
  `"source": "./"`; each host reads its own root manifest. This is how
  `obra/superpowers` serves nine hosts from one tree.
- **Codex gets its tools back.** The marketplace listed one plugin pointing at
  `./plugins/claude-code`, so `codex plugin add` installed the Claude bundle —
  which carries no `.codex-plugin/plugin.json`, the only place Codex looks for
  `mcpServers`, `skills` and `hooks`. `plugins/codex/` was never installed by
  anything, and `make plugins-check` stayed green throughout.
- **No version pin anywhere.** The MCP config is now
  `uvx --from "${CLAUDE_PLUGIN_ROOT}" ach-memory mcp`, so the proxy is built
  from the checkout the host installed and updating the plugin updates the
  proxy. The old config baked `@v<version>` in at release time and the host
  froze it at install time: opencode and pi were stranded on 0.3.1, and Codex
  on `@v0.7.1`, a tag from the deprecated predecessor that does not exist.
- **`ach-memory init` is removed** (`-93` lines), along with the packaged copy
  of `plugins/` in the wheel. The four native commands replace it.
- **New events.** Codex gains `PreCompact` (it supports it, and `SubagentStart`
  and `SessionEnd` besides); opencode gains `experimental.session.compacting`.
  `docs/hosts.md` is now a parity table, and it marks pi's two gaps as host
  limitations with the event list that proves it.
- **`tests/test_plugins.py`**: every declared manifest path exists, each hook
  file names only its own plugin-root variable, both hosts declare the same
  events, the hook scripts are executable, no MCP arg carries a version pin,
  and exactly one `SKILL.md` exists. This is the class of failure that shipped
  unnoticed through four releases.
- `pre-compact.sh` no longer uses `exec`: `exec cmd || fallback` reaches the
  fallback only when the shell cannot launch `cmd` at all, so uvx failing after
  launch printed nothing.

No service change: the API, the chart and the database are untouched. Every
host must be reinstalled with its command above — 0.4.0 installs keep pointing
at the old pinned sources.

## 0.5.1

`package.json` no longer carries a `files` allowlist. It left `pyproject.toml`
and `src/` out of the npm package, so opencode and pi installed a bundle whose
`uvx --from <package dir> ach-memory mcp` had no project to build:
`MCP error -32000: Connection closed`. Claude Code and Codex were unaffected —
they install the tree directly, not through npm.

## 0.5.2

The opencode plugin no longer sets `environment` on its MCP entry. opencode
interpolates `{env:VAR}` only in the config file, so a placeholder set from a
plugin reached the proxy as a literal — `Illegal header name
b'{env:ACH_MEMORY_HEADER}'` — and the server died on startup as
`MCP error -32000: Connection closed`. The proxy inherits opencode's own
environment, which is where the credential already is.
