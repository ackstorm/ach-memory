# ach-memory 0.4.0

ach-memory 0.4.0 is the identity, governance and delivery harness around Hindsight. Agents submit one established, independently correctable claim through typed `retain`; ACH authorizes User versus Project scope, sanitizes bounded evidence, records provenance and resolves the opaque physical bank. Hindsight remains responsible for storage, recall, consolidation, reflection and mental-model synthesis.

The release includes:

- one governed built-in mental model per User or Project bank plus five custom models;
- explicit `always_in_context` selection;
- authorized `ach-memory context load` aggregation with no cross-bank synthesis;
- deterministic Project Metadata, active time-bounded claims and explicit Working State;
- a canonical retain/curation skill shared by Claude Code, Codex, OpenCode and Pi;
- clean-install and v0.3.5 forward migration support.

Context is counted with `ach-delivery-o200k-v1`. User models have 1,024 tokens, Project models 2,048, Project Metadata 256, active time-bounded claims 256, Working State 512 and framing 512; the complete response never exceeds 4,608 tokens. Entries are omitted whole, never clipped, and startup fails open if memory is unavailable. A bank whose safety mutation has an unknown upstream outcome is withheld rather than served as current truth.

Retained content is English-only in 0.4.0 because the deployed Hindsight reranker is English-only. Updating a built-in definition can temporarily withhold that model until its refresh operation is proven complete. A User model marked `always_in_context` is available to every authorized agent for that user, so its prompt and source selection must be chosen accordingly.

Compatibility was measured against loopback Hindsight 0.9.2 using disposable banks. The nine-model context read had a 95th percentile latency of 140.2 ms over 30 warmed calls, under the two-second startup ceiling. The two-family retain-skill gate passed all hard thresholds over 120 closed decisions.

Shipping this code does not activate production behavior, mutate production banks, perform data cleanup, publish packages or deploy hosts. Those operations require separate approval.
