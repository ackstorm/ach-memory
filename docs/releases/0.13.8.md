# 0.13.8

- **The plugin loads on OpenCode 2.** OpenCode 2 loads only a default export
  with an `id` and a `setup`; the plugin had a named export, so the host
  skipped it and ran with no memory at all, saying so only in the server log
  (`opencode run --standalone --print-logs`). The plugin now has both entry
  points: `setup` for OpenCode 2, the existing hooks for OpenCode 1.
  `package.json` gained `exports`, which OpenCode 2 reads to find the plugin
  in a local directory.
- **OpenCode 2 installs with `opencode plugin add <git spec>`.** It refuses the
  service URL (`/plugin`); that install path stays OpenCode 1 only.

Deploy: the plugin. The server is unchanged apart from its version.
