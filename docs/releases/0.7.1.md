# 0.7.1

- **The turn-finished retain nudge is gone.** A `Stop` hook cannot reach the
  model except through `decision: "block"` or exit 2, and the host renders
  either as a hook error; `Stop` is deliberately excluded from the four events
  whose stdout becomes context, so there was no other path. Rather than rework
  it, the nudge is removed: 0.7.0's idle nudge already does the job on every
  host through a supported path (`UserPromptSubmit`, `chat.message`,
  `before_agent_start`) and rides into a turn the user already started, where
  the turn-finished version cost an extra turn on all four hosts. Gone with it:
  `hooks/scripts/stop.sh`, `hooks/scripts/retain-nudge.sh`, the
  `ach-memory hook retain-nudge` subcommand, opencode's `session.idle` handler
  and pi's `agent_settled` handler, and both `stop_hook_active` emulations those
  two carried.
- **Breaking: `ACH_MEMORY_NUDGE_INTERVAL` no longer exists.**
  `ACH_MEMORY_IDLE_INTERVAL` (seconds, default `1800`) is now the only nudge
  clock. Nothing is wired to the host's "turn finished" event.
- What this gives up: nothing nudges when the user stops prompting altogether,
  before a `/clear` or walking away. The idle stamp is keyed on the checkout
  rather than the session, so the next prompt still nudges, even in a fresh
  session; what is lost is retaining a claim whose context died with the
  `/clear`.
- **`retain` no longer rejects a URL whose userinfo carries no password.**
  `scheme://user@host` is the shape of an ordinary ssh git remote, and naming a
  repository's clone URL in a claim was refused as a secret with
  `CONTENT_REJECTED_BY_SANITIZER` and no indication of which span offended. The
  password form still rejects, and a token used as the username still trips the
  token patterns.

No service change; the release is the plugin.
