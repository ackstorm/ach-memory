# 0.13.18

- **A project's memory can be shared.** Each project has one access list of users
  (emails) and groups (ACH teams), and everyone on it is a co-owner: they read,
  write, share, unshare and rename, and can remove anyone else, its creator
  included. `share` accepts only groups the caller belongs to; `unshare` never
  empties the list. Personal memory is never shared.
- **New tools and commands.** MCP tools `whoami`, `list_access`, `share_project`
  and `unshare_project`; CLI `ach-memory whoami`, `ach-memory share [user|group
  NAME...]` and `ach-memory unshare user|group NAME...`. The skill's new
  `references/sharing.md` lets an agent share on request ("share this project
  with Joan Pau") and answer with who has access.
- **Migration `0008`.** `projects.access` replaces `owner_type`/`owner_id`: a
  user owner becomes the subjects of their identities, a group owner its group.
  It refuses to run while a user owner has no identity (production: 0 of 32
  projects, checked 2026-11-26).

Deploy: the server (migration runs before it serves) and the plugin. A group
reaches ach-memory only once its team is in the `authorizedTeams` of an
Environment that grants ach-memory (`grants`).
