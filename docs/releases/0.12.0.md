# 0.12.0

Breaking release. Session start no longer comes from LLM-written views: it is
built from titles, families and pins that ACH stores next to its journal.

- **Session start, in order:** the project's purpose; your pinned memories in
  full; the project's pinned memories in full; an index of the project's
  memory, one line per family with its count and its three newest titles
  (below 30 memories, the plain list of titles); one line of totals. Pinned
  memories are not repeated in the index's titles. When the index does not
  fit, it keeps every family and drops sample titles first. Without a
  project you get your own pinned memories instead of nothing. Everything the
  hook prints stays under 10,000 characters. Claude Code and Codex print it
  again after a compaction; opencode and pi keep it in the system prompt.
- **`retain` takes `title`** (required, at most 80 characters), **`family`**
  and **`pin`**. A project gets a closed list of at most 12 families plus
  `other` when it first holds 30 memories; from then on every project retain
  must name one of them, and an unknown family is refused with the list.
  `ach-memory families` shows the list and `ach-memory families set` edits it.
  A drafted list names no family after the project and puts no more than
  about a third of the memories in one family.
- **Pins are capped:** 3,500 characters of pinned text per project, 2,000 per
  user. A pin past the cap is refused (`PIN_CAP_EXCEEDED`) with what is
  pinned. New tool `pin` pins and unpins; both are journaled.
- **Reading:** `list_memories` lists titles and ids, filters by `family`,
  `memory_types` and `pinned`, and returns the text only with `full=true`.
  `recall` and `get_memory` results carry the title, family and pin.
- **No derived views.** The four built-in mental models are gone, with
  `load_context(model=...)`. Consolidation is off on every bank
  (`enable_observations=false`). `reflect` stays; it still reads the
  observations written before, and now treats them as stale.
- **Read log.** Every session-start load, `recall`, `list_memories` and
  `get_memory` is recorded in `read_events`: who, project, tool, query or
  family, result count and latency. The `read_daily` view sums them per day,
  project and tool.

## Rollout

1. Deploy 0.12.0. Migration 0005 adds the `memories` and `read_events`
   tables and `projects.families`. Set `config.llm` in the chart so a project
   reaching 30 memories gets its family list; unset, families stay optional.
2. Run `scripts/rollout-0.12.py apply PLAN` with the plan from a fresh
   `plan` run. Per bank it deletes the mental models, turns consolidation off,
   stores the family list and one record per memory with its title, family and
   original creation time. An LLM rates every memory: `critical` (breaking
   it does serious or irreversible harm in any task), `always` (applies to
   every task) or `scoped` (one component or kind of task). Critical ones are
   pinned first, then always ones, newest first, until the bank's cap; scoped
   ones never. In the ach-memory project it also forgets the memories that
   only describe the removed views, with a reason in the journal (`restore`
   brings one back). Until it runs, session start lists only memories
   retained since the deploy.
3. Update the plugin on every host for the new skill and activation text.

The `briefing` memory type remains for older memories; pin instead.
