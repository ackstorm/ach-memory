# 0.10.3

- **`postgresql://` database URLs work.** `MEMORY_DATABASE_URL` accepted only
  `postgresql+psycopg://`; a plain `postgresql://` or `postgres://` URL, the form
  CloudNativePG and libpq tools hand out, made SQLAlchemy look for psycopg2 and
  fail at startup. The service and the migrations now pin both schemes to
  psycopg 3, so a deployment can pass the generated URL as is.

Server change only; it takes effect on deploy. URLs that already name
`postgresql+psycopg://` behave as before.
