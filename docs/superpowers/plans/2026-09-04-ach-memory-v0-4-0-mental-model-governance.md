# ach-memory v0.4.0 Mental-Model Governance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Hindsight mental models into an authorized ACH product surface with stable logical identities, one versioned built-in per bank, five additional custom slots, explicit delivery selection and idempotent MCP bootstrap.

**Architecture:** Hindsight continues to synthesize and store each model. ACH stores only governance metadata and operation state in the registry created by the foundation plan, addresses models by immutable ACH `model_key`, and resolves upstream IDs internally. User and Project built-ins are compiled definitions, not an extensible template system; custom models use the same authorized lifecycle without being adopted or rewritten automatically.

**Tech Stack:** Python 3.12, FastAPI/Pydantic 2, SQLAlchemy 2, Hindsight 0.9.2 mental-model API, FastMCP, pytest/respx.

**Spec:** `docs/specs/2026-09-03-ach-memory-v0.4.0.md`

**Execution branch:** Create `feat/ach-memory-v0.4.0-mental-models` from the verified foundation HEAD and record that SHA in the execution notes before Task 1.

## Global Constraints

- Requires the verified HEAD from `2026-09-04-ach-memory-v0-4-0-foundation.md`.
- May execute in parallel with typed-retain/lifecycle; do not add migrations or edit `src/memory/mcp/memory_tools.py`, retain, curation or expiry services.
- One ACH built-in exists outside the five-custom-model quota in each physical bank; the normal maximum is six ACH-governed models per bank.
- Custom `model_key` is generated by ACH, immutable and public; `upstream_model_id` and `bank_id` remain internal.
- Every persisted model selects both `schema:ach-retain-v1` and `validity:indefinite`; expiring claims are rejected as model sources.
- `always_in_context` is required on custom creation and never inferred from name, prompt or scope.
- User built-in budget is 512 tokens; Project built-in budget is 1,024 tokens.
- Hindsight's supported minimum is 256 tokens per model. Enabling `always_in_context` is rejected transactionally when the enabled models would exceed 1,024 User tokens or 2,048 Project tokens; registration quota never implies delivery eligibility.
- Built-in definitions are immutable through custom-model CRUD, versioned, automatically provisioned by default, and never re-enable a user's disabled delivery choice.
- Unknown upstream models are inventoried only; they are not adopted, counted, mutated or deleted.
- Ordinary model list/get and context reads never provision or reconcile definitions.
- No production model or bank is mutated by tests; live tests use explicit disposable-bank confirmation and guaranteed cleanup.

Creation validates exact required source tags and `max_tokens >= 256`, locks the logical-bank quota row set, writes a `creating` registration with generated key and canonical mutation hash, commits, calls the existing trusted Hindsight mental-model methods, then records its internal ID and `active` lifecycle. The foundation has frozen the client method signatures; do not edit the shared client from this parallel branch. A retry with the same operation ID and payload returns the same registration. A different payload conflicts. If the response was lost, list upstream models by that exact internal name and adopt only one whose prompt, tags, budget and trigger all match; zero matches retries creation, multiple or mismatched matches require operator action.

Amend SPEC §7.2 to state this public-display/internal-locator split explicitly; public responses and logs still never expose the upstream mental-model ID.

- [ ] **Step 3: Implement exact completion and failure state**

- [ ] **Step 4: Implement at-most-one access-driven repair**
