# Session Brief — Design

**Status:** approved for implementation, 2026-08-27
**Depends on:** `HINDSIGHT_API_REFLECT_LLM_MODEL: gemini.gemini-3.7-flash` in the deployed
Hindsight. Without it every mental-model refresh fails and no brief can be generated.

## Problem

Memory only pays off when it is read, and reading requires the agent to know there is
something worth reading. Measured 2026-08-27 in this repository's own test suite
(`tests/test_agent_bundle.py:341`): an agent with the activation text loaded and the MCP
server connected ran `recall` and `list_memories` without ever opening the skill, and a
second one, told to remember something, wrote it to the host's file store instead. Storing
is solved. Retrieval at the right moment is not.

A session brief closes that gap from the other side: instead of relying on the agent to ask,
the session starts with a short digest of what memory already knows.

## What it is

Two digests, delivered as text at session start:

- **user** — the practical standing instructions this person has stated: how they want an
  agent to work, their language, their tools.
- **project** — what has been learned about this codebase, drawn from its stored memories.
  Not a description of the repository, which the agent can read for itself.

They are **orientation, not authority**. The brief is generated by an LLM from stored facts
and can be wrong in ways a single memory cannot: it arrives with no citation and no obvious
way to check it. Measured during design, a loose digest of this user's memories inverted one
of his rules — "after each change run a full test gate" where the stored fact says never to
run the full suite after a small change — and invented a role and a toolset for him that no
memory contains. The delivered text therefore states its own status and points at `recall`
as the authority.

## Why mental models

Hindsight's mental models are exactly this primitive and are already wrapped in
`src/memory/hindsight/client.py`. A mental model is a stored document plus the
`source_query` that generates it. The generating `reflect` runs on refresh; **reading the
document is a SELECT**. That is what makes a per-session read affordable: the LLM cost is
paid when memory changes, not when a session starts.

They stay off the MCP tool surface, as SPEC §14.2/§14.4 requires and
`tests/test_mcp_tools.py:1094` enforces: a mental model feeds reflection for everyone on a
project, so managing one is governance an agent must not grant itself. The brief provisions
them server-side instead.

## Architecture

```
agent host
   │  spawns
   ▼
ach-memory mcp (stdio proxy)          ach-memory (server)          Hindsight
   │  GET /v1/session-brief ─────────▶ │                              │
   │                                   │ resolve banks (principal)    │
   │                                   │ provision MMs if absent ────▶│
   │                                   │ read MM documents ──────────▶│
   │  ◀──── instructions text ─────────│                              │
   │                                                                  │
   └─ sets proxy.instructions ─────────▶ reaches the model at initialize
```

**The endpoint returns the whole instructions payload — policy text and brief together —
not the brief alone.** The proxy forwards the remote server's instructions verbatim while it
advertises none of its own (verified live), and setting its own replaces them. Composing
server-side keeps one source of truth and gives the failure path for free: if the fetch
fails, the proxy sets nothing and the model receives exactly today's policy text.

### Why the server composes it

The design lesson of this project so far is that the value lives in the `source_query` and
the output format, not in the model. The same model over the same memories produced 3364
characters with an inverted rule and an invented biography under a loose query, and 1438
correct characters under a strict one. Those two artefacts must be changeable with a deploy.
Putting them in the proxy would mean a release, a tag, and a `plugin update` on every host
to fix a hallucination — measured today at hours.

## Components

### 1. `GET /v1/session-brief` (new)

Query parameters: the standard scope resolution ones (`project_slug`, `git_locator`), both
optional. Authentication and bank resolution reuse the existing pipeline; this route adds no
permission model.

Behaviour:

1. Resolve the user bank from the principal. Resolve the project bank only if the request
   carries project context, using `create=False` — a brief must never mint a project.
2. For each resolved bank, ensure the brief's mental model exists (below), then read it.
3. Compose and return.

Response:

```json
{
  "instructions": "<policy text + brief sections>",
  "generated_at": "2026-08-27T03:00:00Z",
  "sections": {"user": true, "project": false}
}
```

`sections` and `generated_at` exist for the CLI hatch, so a human can see why a section is
missing without reading the prose.

### 2. Provisioning (server-side, internal)

On each call, for each bank: look for a mental model named `ach-memory-session-brief`.

- Absent → create it with the source query from code, `max_tokens`, and
  `trigger: {mode: "delta", refresh_cron: "0 3 * * *"}`. Return without a section this time:
  the content is `"Generating content..."` until the first refresh completes.
- Present but its stored `source_query` differs from the one in code → `PATCH` it. Hindsight
  falls back from `delta` to a full regeneration automatically when the query changed, so a
  deploy that improves the query takes effect on the next refresh with no special handling.

Creation and update never reach the MCP surface and are never driven by a model.

**Refresh policy:** `delta` mode preserves unchanged sections byte-for-byte, so a
regeneration cannot quietly reword a line that was already right. The nightly cron (03:00
UTC) only runs when the model is stale — no new memories in scope means the tick is skipped
and no LLM call is made. `refresh_after_consolidation` is deliberately not used: it would
fire a `reflect` mid-session every time the agent retains something.

### 3. The source queries (code, versioned, tested)

Two constants. The user one is the exact query validated during design; it produced correct,
non-inventing output on real memories:

> List only the standing instructions this user has explicitly stated about how an agent must
> work with them: process rules, communication and language, and tools they named. Write each
> as one short imperative line an agent can follow. State only what the memories say. Do not
> infer their role, employer, seniority or any tooling they did not name. Omit colour,
> styling and theme preferences entirely. No headings, no tables, no summary paragraph.

The project one keeps every constraint of it and changes only the subject:

> List only what has been learned about working in this codebase: conventions that are
> followed, constraints that hold, and gotchas together with their cause. Write each as one
> short line an agent can act on. State only what the memories say. Do not infer the
> project's purpose, architecture or technology from its name, and do not describe what the
> repository's files would already show. No headings, no tables, no summary paragraph.

Both are created with `max_tokens: 400`, the value the validated run used.

Every clause in them is load-bearing and was earned: the anti-inference sentence removed an
invented role, and the formatting rules took the output from 3364 characters to 1438.

### 4. Composition

```
<policy text, exactly as today>

── What memory knows about you ──
(orientation, generated from stored facts — verify with recall before acting on it)
<user digest>

── What memory knows about <project slug> ──
<project digest>
```

Rules:

- A section whose bank has no material is **omitted entirely**. An empty digest is where a
  model starts inventing, and a heading with nothing under it invites exactly that.
- A section is omitted when its mental model is stale AND has not refreshed in seven days.
  That pair means refreshes are failing, which is invisible otherwise: a failed refresh keeps
  serving the previous content and does not set `is_stale`. Staleness alone is not enough —
  a user who wrote nothing for a week has a legitimately old, correct digest.
- `max_tokens` is advisory upstream, measured at ~850 tokens returned for a 512 request, so
  each section is hard-truncated at the endpoint with a visible marker.

### 5. Proxy fetch

At startup, before serving: one request with a 2 second timeout. On success, set
`proxy.instructions`. On any failure — timeout, auth, non-200, malformed body — set nothing
and log one line to stderr. Session start must never block on memory and must never fail
because of it.

No local cache in v1. The read is a SELECT server-side plus one HTTP round trip; a cache is
a correctness surface (staleness, invalidation, a file per bank) bought against a cost that
has not been measured. If startup latency turns out to be felt, that is a measurement and a
follow-up, not a guess made now.

### 6. `ach-memory brief` (CLI)

Prints exactly what would be injected, then a metadata footer: `generated_at`, which sections
are present, and why one is missing. Same URL and credential resolution as `ach-memory mcp`.

This is the escape hatch for the failure mode the design cannot prevent. When a brief is
subtly wrong, the symptom is an agent behaving oddly for no visible reason; without this,
diagnosing it means guessing at text nobody can see.

## Out of scope for v1

- **Tags.** ach-memory writes no retrieval tags at all (`hindsight/client.py:251`, SPEC
  §13.6), so tag filters would filter on something no memory carries — and a mental model
  that has tags defaults to `all_strict`, which would exclude every existing untagged memory
  and produce an empty brief. Tagging is a write-path feature with its own taxonomy, its own
  decision about who assigns a tag, and a backfill question. It gets its own spec; the brief
  adopts it later through configuration.
- **Human-curated briefs.** The natural evolution once the brief proves its worth is
  approving a digest and freezing it. It is not needed to find out whether it is worth
  anything.
- **Migrating the memories in the retired `ach-memory` project slug.** Unrelated to this
  work and already recorded.

## Global constraints

- No new MCP tool, and no mental-model management reachable by a model.
- Session start never blocks on, and never fails because of, memory.
- The brief is orientation; the delivered text says so and names `recall` as the authority.
- Content is English; the composed text carries no credentials.
- Bank resolution and authorization go through the existing pipeline unchanged.

## Success criteria

1. A fresh agent host with no configuration receives, at `initialize`, the policy text plus a
   user section carrying that user's real standing rules.
2. A project with no memories produces no project section, and no invented one.
3. With the server unreachable, the session starts normally and the model receives the policy
   text alone.
4. `ach-memory brief` prints the same text the model received.
5. A changed source query in code reaches the next refresh with no manual step.
